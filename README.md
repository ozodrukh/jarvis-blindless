# Джарвис: первый рабочий прототип

Голосовой помощник на русском для Mac с Apple Silicon. Управляет заранее подготовленными аудиокнигами и свободно общается. Без файла настроек использует локальные Gemma 4 E4B, Whisper и голос macOS. В файле можно независимо выбрать онлайн-распознавание, LLM и озвучку: при ошибках они переходят на существующие локальные модели. Обращение по имени всегда распознаётся на Mac.

## Как подготовить Mac друга

Нужны Mac M1 или новее, macOS 14 или новее, 16 ГБ памяти и примерно 12 ГБ свободного места для первоначальной установки. Скорость и удобство на обычном M1 предстоит проверить с пользователем.

1. Распакуй комплект в постоянную папку, например `Документы/Джарвис`. После настройки оставляй всю папку на этом месте: приложение использует среду запуска рядом с собой.
2. С интернетом открой `Настроить Джарвиса.command`. Будут установлены локальные библиотеки, Python и модели. Веса Gemma занимают около 5,2 ГБ, модель для обращения по имени — около 75 МБ. Шаг может занять несколько минут. Терминал нужен только при этой подготовке.
3. Открой `Джарвис.app`, разреши микрофон и выбери папку `audiobooks` из комплекта. В ней есть две короткие демонстрационные книги.
4. Для онлайн-режима скопируй `jarvis-config.example.json` в личный файл, заполни модели, ключ и голос. Нажми «Выбрать настройки…» в приложении. Файл проверяется, его расположение запоминается; после изменения содержимого нажми «Перечитать». Подробности ниже.
5. Проверь русскую локальную озвучку для резервного режима. Если русского голоса нет, заранее установи его в настройках универсального доступа macOS: «Чтение и речь» / «Устный контент», русский голос «Милена». Название раздела зависит от версии macOS.
6. Отключи сеть и проверь разговор и книги. После перезагрузки другу помогут войти в macOS и запустить приложение.

Это локально собранный прототип с временной подписью, без нотариального заверения Apple. При переносе на другой Mac первоначальный запуск может потребовать помощи владельца через «Открыть всё равно» в настройках безопасности. Разрешать микрофон и готовить библиотеку нужно один раз при настройке.

## Как пользоваться

Скажи: «Джарвис, какие у меня книги?» Обращение приостанавливает книгу, затем звучит короткий сигнал. Можно произнести имя и просьбу одной фразой. После ответа можно продолжать без имени. Скажи отдельной фразой «закончили», «конец разговора», «заверши разговор» или «end chat», чтобы закончить: Джарвис остановит ответ и вернётся к ожиданию имени. Книга останется на паузе. Тишина тоже заканчивает разговор: по умолчанию через 15 секунд, время настраивается. Когда книга играет, снова используй имя.

Примеры:

- «Джарвис, продолжи последнюю книгу».
- «Включи Небольшую прогулку».
- «Где я остановился в Проверке Джарвиса?»
- «Поставь книгу на паузу».
- «Начни книгу сначала» → Джарвис уточнит → «Да» или «Отмена».
- «Расскажи короткую добрую историю».

Окно можно закрыть: помощник остаётся в строке меню. Там можно открыть окно, поставить книгу на паузу, остановить ответ, выключить микрофон или завершить приложение. Кнопка «Слушать запрос» позволяет отдельно проверить диалог, если обращение по имени пока срабатывает плохо. Текстовый запрос в окне помогает проверить модель без микрофона.

При выключенном микрофоне распознавание прекращается. В спящем состоянии Mac приложение не слышит обращения. Команда, которая прерывает длинный ответ, начинается с имени: «Джарвис, отмена».

## Онлайн-модели и файл настроек

Пример рядом с приложением не содержит ключа. `YOUR_LLM_MODEL`, `YOUR_TTS_MODEL` и `YOUR_VOICE_ID` нужно заменить идентификаторами выбранного сервиса; для озвучки проверь поддержку русского языка и указанного голоса. Никакая платная модель автоматически не выбирается. Отсутствующий ключ приводит к локальному резерву.

В разделах `stt`, `llm`, `tts` поле `mode` выбирает `online` или `offline`. При `offline` поле `model` должно быть соответственно `whisper`, `gemma` или `macos`. При `online` нужны модель и `base_url`, например `https://openrouter.ai/api/v1`. LLM использует Chat Completions, TTS — Audio Speech с форматом ответа из `tts.response_format` (по умолчанию MP3). `response_format` у LLM можно переключить с `json_schema` на `json_object` или `text`, если сервис не поддерживает строгую схему; результат всё равно проверяется приложением.

Для онлайн-STT замени раздел распознавания, например:

```json
"stt": {
  "mode": "online",
  "model": "openai/whisper-large-v3-turbo",
  "base_url": "https://openrouter.ai/api/v1",
  "api_key_file": "openrouter.key",
  "api_format": "openrouter",
  "language": "ru"
}
```

`api_format: "openrouter"` отправляет WAV как base64 в JSON. Для стандартного OpenAI-совместимого multipart-запроса поставь `"openai"`. LLM, распознавание и озвучка могут использовать разные адреса и ключи. Перед онлайн-распознаванием есть короткая локальная проверка команды завершения разговора; она сохраняет возможность закончить чат при недоступной сети. В локальном режиме Gemma по-прежнему получает исходное аудио вместе с расшифровкой.

Ключ можно указать в `api_key` личного JSON, в UTF-8-файле через `api_key_file` (относительный путь считается от JSON) или через имя переменной окружения `api_key_env`. Порядок выбора: непустой `api_key`, затем файл, затем окружение. GUI-приложение обычно не получает переменные из настроек shell, поэтому отдельный файл ключа удобнее. В каждом онлайн-разделе можно сослаться на один `openrouter.key`. Не клади личный файл и ключ в комплект для друга или репозиторий. Приложение запоминает только путь к JSON; не копирует ключи в настройки macOS.

### Формат озвучки

В разделе `tts` поле `response_format` выбирает формат запроса: `mp3`, `pcm`, `opus`, `wav`, `flac` или `aac`. Выбранная модель и сервис должны его поддерживать. Приложение не меняет формат автоматически и не повторяет синтез в другом формате. Старые файлы без этого поля продолжают запрашивать MP3. Для OpenRouter сейчас документированы MP3 и PCM; Gemini TTS принимает PCM.

Для текущей модели Gemini достаточно добавить в свой раздел `tts`:

```json
"response_format": "pcm",
"pcm_sample_rate_hz": 24000,
"pcm_channels": 1
```

Это фрагмент полей существующего раздела, а не отдельный JSON-файл. `pcm_sample_rate_hz` (8000–96000, по умолчанию 24000) и `pcm_channels` (1 или 2, по умолчанию 1) описывают raw PCM, если сервис не указал частоту и каналы в `Content-Type`. Параметры ответа имеют приоритет. Поддерживается signed 16-bit little-endian PCM; приложение добавляет WAV-заголовок для воспроизведения. Эти два параметра не отправляются сервису и не меняют частоту в его ответе.

Для `opus` поддерживается контейнер Ogg, для `aac` — ADTS. WebM/Opus и M4A не являются их синонимами. Ogg/Opus декодируется установленной при подготовке библиотекой; FFmpeg и Homebrew для работы не нужны. MP3, WAV, FLAC и ADTS AAC воспроизводятся средствами macOS. Ограничение 16 МБ действует и на ответ, и на подготовленный звук; ошибки формата или декодирования включают локальный резерв. После изменения JSON нажми «Перечитать».

`network.max_retries` — число повторов после первой попытки, по умолчанию один. Временные ошибки, 408, 429 и 5xx повторяются с задержкой; неверный ключ и модель сразу переводят на локальный резерв. `timeout_seconds` ограничивает одну попытку, `total_timeout_seconds` — общее ожидание онлайн-сервиса на этапе, `retry_delay_seconds` задаёт начальную задержку. Следующий запрос снова попробует онлайн-сервис; перезапуск после восстановления сети не нужен. Озвучка переходит на голос macOS без повторения уже выполненного действия.

`conversation.silence_timeout_seconds` задаёт ожидание новой реплики (1–600 секунд); `end_phrases` — отдельные команды завершения. `audio.end_silence_seconds` задаёт паузу внутри реплики перед её отправкой (0,3–5 секунд). Это разные интервалы. Максимальная запись — 28 секунд.

В окне под разговором показываются фактические модели, время каждого этапа и пометка «резерв», если онлайн-сервис не сработал. Время распознавания включает локальную проверку команды завершения. «Подготовка ответа» измеряется после отправки реплики до получения готовой озвучки, исключая длительность произнесения ответа. Это позволяет сравнивать настройки на одинаковых запросах.

## Если приходится говорить громко

В окне есть индикатор уровня микрофона. Говори обычным голосом, сначала в тихой комнате, затем с книгой из динамиков. Если индикатор почти не двигается во время речи, проверь выбранный микрофон и уровень входа в настройках звука macOS. Если показывает «Слишком громко», уменьши уровень.

Приложение использует локальное определение речи, более низкие пороги для тихого входа и ограниченное усиление перед распознаванием. `audio.speech_threshold`, `wake_threshold`, `vad_threshold`, `normalize_gain_limit` и `target_rms` позволяют настроить чувствительность; слишком низкие пороги могут усилить шум. `voice_processing` включает доступную обработку голоса AVAudioEngine; если устройство её не поддерживает, обычный захват продолжает работать. Это не гарантия подавления всего звука из динамиков. Удобство живой речи и ложные срабатывания нужно проверить на конкретном Mac.

## Свои аудиокниги

В выбранной папке должен быть `meta.json`:

```json
{
  "version": 1,
  "books": [
    {
      "id": "master-margarita",
      "title": "Мастер и Маргарита",
      "author": "Михаил Булгаков",
      "aliases": ["Мастер"],
      "files": ["master/01.mp3", "master/02.mp3"]
    }
  ]
}
```

`id`, `title` и непустой список `files` обязательны. `author` и `aliases` необязательны. Файлы идут строго в указанном порядке; пути задаются относительно папки библиотеки. Используй MP3, M4A, M4B, WAV или AIFF, поддерживаемые AVAudioPlayer; зашифрованные аудиокниги не поддерживаются. После изменения JSON снова выбери ту же папку в приложении.

Сохраняй `id` книги и относительные имена её файлов при обновлении библиотеки: позиция привязана к ним. Если сохранённая часть удалена, приложение попросит проверить библиотеку или начать книгу сначала, сохранив прежнюю позицию до подтверждения.

## Что сохраняется

Папка библиотеки, последняя книга и позиция каждой книги хранятся в `~/Library/Application Support/Джарвис/progress.json`. Запись атомарная: каждые 2 секунды воспроизведения, при паузе и завершении. При аварийном выключении может потеряться до нескольких секунд с последнего сохранения. Переключение между книгами сохраняет каждую позицию отдельно.

История диалога остаётся только в памяти процесса и очищается при завершении разговора. Запись запроса временно создаётся локально и удаляется после обработки. При принудительном завершении процесса временный файл может остаться в системной временной папке. В ожидании имени аудио в сеть не отправляется. При выбранном онлайн-STT отправляется запись запроса, онлайн-LLM получает текст, краткую историю и состояние библиотеки, онлайн-TTS — текст ответа. Без выбранного онлайн-режима эти данные остаются на Mac. Технический журнал запуска находится рядом с моделями: `.runtime/voice.log`; ключи и записи речи в обычные диагностические события не включаются.

## Что важно проверить с другом

Пошаговый сценарий находится в файле «Проверка с другом.md» из комплекта и в `docs/testing-with-friend.md` проекта. Особое внимание — имени поверх книги из динамиков, задержке ответа, ложным срабатываниям и возможности продолжить без посторонней помощи.

Обращение по имени в прототипе использует небольшую локальную Whisper, проверяющую скользящие фрагменты речи; это ещё не специально обученный детектор ключевого слова. Выделение реплики использует Silero VAD из уже установленного faster-whisper и настраиваемую паузу. Работа в шуме и перебивание из динамиков нуждаются в проверке на реальном устройстве. Модели могут ошибаться в разговоре. Действия плеера ограничены кодом приложения.

## Для разработчика

Исходники: `Sources/Jarvis` — окно, плеер, микрофон и связь с моделью; `Sources/JarvisCore` — библиотека и сохранения; `voice` — локальный голосовой процесс.

```sh
# Зависимости локального голосового процесса
uv venv --python 3.12 .runtime/venv
uv pip sync --python .runtime/venv/bin/python voice/requirements.lock
.runtime/venv/bin/python voice/setup_models.py --runtime .runtime

# Демозаписи и проверки настоящей модели, без микрофона
bash scripts/create_demo.sh
.runtime/venv/bin/python voice/check_models.py --runtime .runtime

# Проверки логики и сборка
bash scripts/test.sh
.runtime/venv/bin/python voice/check_stream.py --runtime .runtime --gain 0.03
bash scripts/build.sh
bash scripts/package.sh
```

Для сборки нужны Xcode / Command Line Tools и `uv`. На Mac друга компилятор не требуется: комплект содержит готовое приложение и инструмент первоначальной подготовки. Результаты проверок на этом компьютере сохраняются в `.runtime/check-results.json`; они не заменяют испытание с другом на его M1.

Историческая концепция: `docs/ideas/jarvis.md`; её требование полностью локальной работы заменено согласованной картой `CAPABILITY-MAP.md` и модульными `SPEC-*.md`. Архитектурное решение — `docs/architecture/agent-framework-review.md`. YouTube, Telegram, долговременная память бесед и пересказ содержимого книг в этот прототип не входят.
